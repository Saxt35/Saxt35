# Featured Repository Standard

Every featured architecture repository should progressively answer:

1. Problem — what real problem is addressed?
2. Scope — what is and is not included?
3. Architecture — how are components organized and why?
4. Decisions — which alternatives were considered? Use ADRs.
5. Implementation — how can the project be understood or run?
6. Tests — what behavior is verified?
7. Evaluation — how is quality measured?
8. Security — threats, secrets, permissions and data handling.
9. Resilience — failure modes, fallback and recovery.
10. Observability — what can be measured/traced?
11. Limitations — what does the project not prove?
12. Roadmap — what is next and why?

## Evidence labels

- **DEMONSTRATED:** implemented and reviewable.
- **POC:** implemented in a controlled proof of concept.
- **LAB:** active academic/portfolio experimentation.
- **PLANNED:** designed but not yet implemented.

Never silently promote PLANNED/LAB work to demonstrated professional experience.
